# 法說會大平台 交接說明

給接手的 TEJ 同仁。這份文件說明網站怎麼組成、日常要怎麼加減內容，以及之後有更多資源時可以往哪裡做。

最後更新：2026-11-14

---

## 1. 現在的狀態

| 項目 | 數量 |
|---|---|
| 行事曆收錄 | 252 家公司、482 場法說會（TEJ 逐字稿資料庫 2026 年，只用公司、日期與擇要說明） |
| 完整儀表板 | 21 家公司、24 場，全部是公開版（只保留引用的原句，不附完整逐字稿） |
| 焦點公司 | 台積電：2025 Q4、2026 Q1、Q2、Q3 四場正式法說會都做成深度儀表板，另有專區頁 |

網站做到這裡就停。之後要讓使用者自己上傳逐字稿、自動產生儀表板，就需要後端（見第 6 節）。

## 2. 架構

```
逐字稿（TEJ xlsx / PDF / docx）
   │  extract_text.py      讀檔、切段、認發言人、刪重複、找上一場
   ▼
transcript.json
   │  Claude + skill       依 SKILL.md 與 references/ 的規則寫 dashboard.json
   │  tone_score.py        語調分數
   │  keyword_count.py     關鍵字次數
   │  render_motion.py     產生單場儀表板 HTML（網站一律加 --public）
   │  check_output.py      逐條核對原句、數字、字數、格式；沒過就退回重寫
   ▼
data/<公司>_<日期>.html     每場一個檔案，資料以 JSON 內嵌在 HTML 裡
   │  integrate.py --site  讀出每場的重點，產生 index.js
   ▼
index.html + index.js + universe.js   →   GitHub Actions 檢查後發布到 GitHub Pages
```

- `index.html` 是整個網站（首頁、行事曆、搜尋、公司頁、焦點公司專區、單場頁），所有頁面都在這一個檔案裡用網址的 `#` 切換。
- `index.html` 必須和 `skill/earnings-call-dashboard/assets/integrated_template.html` 一模一樣。改版面時改模板，再複製過去；`integrate.py` 每次執行也會自動複製。
- `integrate.py` 有兩份（根目錄與 `skill/.../scripts/`），內容必須相同。
- `universe.js` 是行事曆資料，由 `tools/build_universe.py` 從 TEJ 的 xlsx 產生。
- `.github/workflows/` 會在每次推送時執行 `python integrate.py --target . --site --check`，失敗就不發布。

## 3. 日常操作

### 新增一場法說會

照 `skill/earnings-call-dashboard/SKILL.md` 做。產生公開版後加進網站：

```bash
python skill/earnings-call-dashboard/scripts/render_motion.py WORK/dashboard.json --tone WORK/tone.json \
    --keywords WORK/keywords.json --transcript WORK/transcript.json --public --outdir WORK/out_public
python integrate.py --target . --site --add WORK/out_public
```

檔名會自動取「公司_日期」，同一場再加一次會覆蓋舊檔。

### 把一家公司升級成焦點公司

1. 做這家公司的儀表板時，`meta.deep` 設為 `true`，並照 `references/modules.md` 第 12 節補上標準指標（`std`、`num`、`low`、`high`、`unit`）、`voices`（CEO 談展望、CFO 談財務）、每題 Q&A 的 `topic`。檢查程式會要求這些欄位都齊。
2. 至少要有兩場深度儀表板，公司頁就會自動改用專區版面。
3. 想放上首頁的「焦點公司」區塊，在 `integrated_template.html` 的 `SITE.focus` 加上股票代號。

最重要的是單位要跨場一致：營收一律 `US$ billion`（或公司自己慣用的單位，但每場都一樣）、毛利率一律 `%`。財測和實際數字靠「指標代碼 + 期間 + 單位」三者配對，任一個不同就對不起來。

### 改首頁或專區的區塊

所有可調整的設定集中在模板最前面的 `SITE`：

| 設定 | 作用 |
|---|---|
| `SITE.home` | 首頁區塊與順序。可用 `hero intro focus industry panels features foot`，拿掉就不顯示 |
| `SITE.focus` | 首頁要介紹的焦點公司 |
| `SITE.economy` | 有「經濟體」專頁的公司與路徑，例如 `{'2330':'tsmc/index.html'}`；公司頁會改為顯示這一頁，首頁焦點卡片會嵌入它的足跡地圖精簡版（網址加 `#mini`） |
| `SITE.notes` | 時間軸上沒有做成儀表板的場次要顯示的名稱，例如 `'2330 2026-05-26':'UBS 主辦投資人會議'` |
| `SITE.metricGroups` | 專區「各季關鍵數據」要額外比對的項目（依關鍵數據名稱比對，例如 HPC 占比） |
| `SITE.consensus` | 市場共識預估，見下面 |

專區的區塊由 `FOCUS_BLOCKS` 依序產生，每個區塊是一個函式，回傳要顯示的內容；回傳 `null` 時整塊連同目錄連結一起不顯示。要新增區塊，寫一個函式並加進陣列；要拿掉，從陣列刪掉那一行。區塊之間沒有互相依賴。

### 接上市場共識

專區「財測 vs 實際」表格最下面一列是預留給市場共識的位置，目前顯示「待接 TEJ 共識資料」。填入 `SITE.consensus` 後就會出現數字，格式：

```js
consensus:{'2330':{'2026 Q1':{revenue:35.2,gross_margin:64.1,eps:21.5}}}
```

單位要和儀表板相同（營收 `US$ billion`、毛利率 `%`、EPS `NT$`）。比較好的做法是用程式從 TEJ 的分析師共識資料產生一個 `consensus.js`，再讓模板讀取，就不必手改模板。

### 更新行事曆

```bash
python tools/build_universe.py <TEJ 逐字稿 xlsx> universe.js
```

產業分類與各產業的指標公司寫在 `tools/build_universe.py` 的 `INDUSTRIES`，加減指標公司改那裡。

### 每次改完

```bash
python integrate.py --target . --site --check
```

通過再推送。網站上的單場儀表板一律要是公開版：每個 `data/*.html` 內嵌資料裡的 `ctx.src` 必須是空的。

---

### 台積電經濟體頁（tsmc/index.html）

單一檔案、資料全部內嵌。重建步驟在 `tools/tsmc_economy/README.md`：用 `words.py` 從逐字稿算詞頻，用 `geo.mjs` 產生地圖與足跡座標，再用 `mk.py` 把 `tpl.html` 和資料組成頁面。原始逐字稿 PDF 不放進儲存庫，只保留算好的詞頻。

## 4. 版面原則

這次改版刻意讓版面可以加減內容而不走樣：

- **一個區塊一件事。** 每個區塊都有標題、一句說明、內容，沒有資料就整塊不顯示，不會留下空框。
- **用設定控制，不寫死。** 首頁區塊、焦點公司、額外指標都在 `SITE`；專區區塊都在 `FOCUS_BLOCKS`。
- **配色與字級只用 CSS 變數**（`--primary`、`--navy`、`--grey`、`--line` 等），深色模式自動跟著變。新增元件時沿用這些變數。
- **紅漲綠跌**，依台股慣例：上修、優於財測是紅色，下修、低於財測是綠色。
- **手機版**：寬表格可以左右滑動，專區目錄在手機上是一條可以橫向滑動的列。

## 5. 成本與時間（實測）

每一場由 Claude 依 skill 產生，再由程式檢查到通過為止：

| 工作 | token | 時間 |
|---|---|---|
| 一般儀表板（8 家新公司，平行產生） | 每場約 15–18.5 萬 | 每場 3–7 分鐘 |
| 台積電深度儀表板，從頭做（2 場） | 每場約 19 萬 | 每場 6–7 分鐘 |
| 既有儀表板補成深度版（2 場） | 每場約 16 萬 | 每場 3–4 分鐘 |

多場可以同時跑。換算成費用要看當時的模型價格。

## 6. 之後有資源可以怎麼做

### 不需要後端，馬上可以做

1. **接上市場共識**：TEJ 已有分析師共識預估，接上後專區就能比較「管理層財測、市場預期、實際結果」三者。
2. **用 TEJ 財報資料補實際數字**：有些場次的逐字稿缺段，例如 2026 Q2 台積電的財務長段落被截掉，毛利率、營業利益率、EPS 沒有出現。實際數字可以直接取 TEJ 的 IFRS 財報資料，不必依賴逐字稿。
3. **更多焦點公司**：聯發科、鴻海、日月光投控等指標公司比照台積電做深度版。
4. **同業比較**：各公司的關鍵數據已經有標準指標代碼，可以做同產業的毛利率、營收成長對照。
5. **歷年資料**：TEJ 資料庫有更早年度的逐字稿，回補後就有「去年同期」對照，也能看更長的趨勢。

### 需要後端

1. **自動產生**：TEJ 資料庫有新逐字稿時自動排程。流程是用 Claude API 的 Agent Skills 載入這個 skill，接著產生 dashboard.json，再由 `check_output.py` 檢查；通過就發布，沒通過就退回重寫，重寫仍失敗就交給人工。
2. **人工審核介面**：發布前讓研究員看一眼，標記要修改的地方。
3. **帳號與通知**：關注清單目前存在瀏覽器裡。有帳號後可以跨裝置同步，並在關注的公司有新法說會時通知。
4. **全文搜尋與議題雷達**：跨公司搜尋「這一季哪些公司提到關稅」，或統計各產業最常被追問的議題。

## 7. 已知問題與待確認

**逐字稿本身的問題**（儀表板已在摘要中說明）

- 台積電 2025 Q4：TEJ 把整場標成同一位發言人，且約 67% 是重複收錄；Q&A 有兩題沒有收錄回答。
- 台積電 2026 Q1：Q&A 中把全年營收成長說成「above 20%」，講稿是「above 30%」；長期毛利率說「53%」，上一場是「56%」。儀表板依講稿，建議對照官方逐字稿。
- 台積電 2026 Q2：財務長段落缺漏，所以專區「財測 vs 實際」的 Q2 毛利率、營業利益率顯示「逐字稿未提及」。

**內容判斷待確認**

- 日月光投控那場的數字可能不是 2026 Q2：基準期提到 2Q24。
- 聯電那場口述的年份前後不一致。
- 鴻海營益率、富邦金 ICS／NIM／CSM 的上修判斷較寬鬆。
- 佳世達、群創是早期的測試案例，沒有評價模組，所以儀表板沒有右側的儀表。

**授權**：公開版仍保留引用的原句。對外正式上線前，請確認 TEJ 逐字稿的使用授權範圍。
