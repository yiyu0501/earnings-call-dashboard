## 第 4 輪　解決四個痛點

**我的要求**
- 「內容帶不走」是最大的問題；我會需要 100 到 300 字的稿，複製下來小改一下就貼給同事
- 原文沒有上下文、上修沒有數字也要處理；英文不用翻譯，「看不懂英文就問 AI」

**決定**
- 首頁直接列出這場的修正項目與前後數字
- 從上一場逐字稿找出原句，補上「前次數值」，並附「上一場原文」按鈕
- 把兩場逐字稿包進頁面，每句原文都能「看上下文」並跳到原處標黃（48 句全部定位成功）
- 新增「報告稿」：LINE 同步、組內摘要、研報重點三種現成的稿，以及從卡片挑選組成的「自己挑」；指引表可整張複製到 Excel

## 第 5 輪　細節修正與透明度

**我的要求**

- 報告稿要有依時間變化的問候語，LINE 同步用條列，組內摘要先總結再條列

**決定**

## 第 9 輪　副標題的語氣

**我的要求**
- 「沒有上修或下修，以下為維持不變的指引」——你真的有上一場的數據嗎？副標題可以用比較正式、像論文的語氣
- 卡片上的「由 58 天下降至 33 天」不用重複大字已經寫的數字

**決定**
- 儒鴻那三項「維持」，上一場確實沒有可對照的數字，是依本場管理層的說法判斷；副標題改為寫明比較基準與判斷依據，例如「比較基準：2026-05-19 法說會。本場未見上修或下修；下列指引判定為維持，惟前次未揭露可對照之數值，係依本場管理層陳述判定。」
- 正式語氣用在說明資料的副標題；操作提示維持白話
- 資料仍存完整的「由 58 天下降至 33 天」，只有卡片顯示時省略與大字重複的部分，規則與檢查不受影響

## 第 17 輪　確定網站的定位

**我的問題**
- 「產生交給 Claude、網站負責瀏覽」是不是表示開發者不用付錢？

**釐清**
- 是。產生儀表板在 Claude 裡完成（claude.ai 或 Claude Code），用的是產生者自己的 Claude 方案，不需要 API 金鑰或伺服器；網站只負責瀏覽、搜尋、比較，訪客免費、不需要 Claude 帳號
- 網站本身不提供「上傳逐字稿自動產生」。若要讓訪客自己產生，必須另架伺服器並付 API 費用（選項 B），或改在 claude.ai 裡做（選項 C），但 C 無法執行 skill 的檢查程式，品質較差

**決定**：採用選項 A，不再開發新功能，下一步是上線。
