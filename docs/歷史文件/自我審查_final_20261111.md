## 二、測試方法

一共四層，缺一層都可能讓錯誤溜過去：

0. **全庫掃描**（`tools/smoke_all.py`）：TEJ 逐字稿資料庫 484 場全部跑過讀檔切段與語調計分，抓程式當掉與資料異常；結果 0 場當掉
1. **回歸測試**（`tools/run_cases.py`）：16 個案例從頭跑完整流程，互動版與表格版都要通過 `check_output.py`
2. **反向測試**（`tools/negative_tests.py`）：故意埋 11 種錯誤，確認檢查程式每一種都擋得下來。只看「沒有報錯」不夠，要確定檢查程式真的會抓
3. **瀏覽器實測**：每個案例在 1440px 與 390px 寬度實際打開、捲完整頁、打開報告稿與方法說明，記錄頁面錯誤與橫向捲軸；`check_output.py` 另外在 375px 寬度檢查

## 三、這一輪找到並修正的問題

| 問題 | 怎麼發現 | 修正 |
|---|---|---|
| 公司名稱被算成語調詞（佳世達的「佳」算了 42 次） | 04 案例的語調詞明細 | `tone_score.py` 計分前遮掉公司名稱；掃過資料庫 252 家公司，目前只有這一家撞到 |
| 語調詞太少時分數失真（群創 1 個詞得 +1.00） | 03 案例 | 少於 10 個正負詞標「詞數太少」 |
| 互動版不支援自訂模組 | 對照投影片第 23 頁 | 補上文字與表格兩種 |
| 提問單位分組寫死，「投顧」消失 | 02 案例 | 依資料動態分組 |
| 375px 寬度多出 8px 橫向捲軸 | 回歸測試的檢查程式 | 窄螢幕隱藏頁首標題文字 |
| 「由 58 天下降」只寫起點 | 使用者發現 | 寫作規則＋檢查程式 |
| 前次數值照抄「mid-to-high 50s」 | 使用者發現 | 規則要求寫出中文意思，阿拉伯數字仍須出現在原文 |
| 報告稿的數字沒人把關 | 自我審查 | 檢查程式核對報告稿每個數字（可接受億與 billion 換算） |
| 書面問答被標成「報告」 | 04 案例 | 規則要求檢查講稿中的書面問答 |
| 同一段內容重複收錄上百次（南亞科 93%） | 全庫掃描 | 刪除重複長句與連續迴圈，並發出警告 |

| 關鍵字程式在上述情況一個詞都算不到 | 07、08 案例 | 與語調程式改用同一套判斷 |
| 和上一場內容幾乎相同（重複收錄） | 09 案例、全庫掃描 | 新增相似度檢查，門檻以實際資料校準 |

## 四、尚未驗證、建議接下來做的事

1. **觸發測試**：在安裝 skill 的對話中分別輸入下列句子，確認前三句會啟用 skill、後三句不會
   - 會：「幫我整理這份法說會逐字稿」（附檔）、「台積電上一場法說會講了什麼」（附 TEJ xlsx）、「把這份 earnings call transcript 做成摘要」
   - 不會：「幫我寫一封法說會邀請函」、「台積電股價為什麼跌」、「幫我做一份法說會簡報投影片」
2. **換模型測試**：已用 Sonnet 跑順達，通過原有全部檢查，並據此補了三條規則。但該次輸入的是 txt，沒測到重複收錄偵測；建議再用 Sonnet 附 xlsx 跑一次順達或儒鴻
3. **第二階段的執行環境**：投影片要求「在桌面建立整合儀表板」，claude.ai 網頁版無法寫入使用者的桌面，需要 Claude Cowork 或 Claude Code；要先和 TEJ 確認展示時用哪一個
4. **詞表**：英文詞表是自行整理的。若要讓語調分數更站得住腳，可以評估金融研究常用的 Loughran–McDonald 詞表，但要先確認授權

## 五、已知限制

- 投資評價、成長動能、風險程度、Q&A 回答態度都是 AI 依規則判斷，沒有程式能檢查對錯；頁面「怎麼算的」分頁已誠實說明
- 語調分數不依「講在多關鍵的地方」加權，因為目前沒有公認的做法；改以「點詞看原句」讓分析師自行判斷
- 上一場逐字稿品質不好時（例如儒鴻上一場斷句混亂），能做前後比較的項目會變少；規則要求沒有根據就不填，不硬湊
- TEJ 原始資料偶有標記錯誤（副總念書面提問被標成「提問方」）或前後數字不一致（同一場營收 100.85 億與 100.86 億），skill 會照原文引用，不會自行更正
