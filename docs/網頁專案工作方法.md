# 網頁專案工作方法

從「法說會大平台」（2026 年 11 月，台灣經濟新報實習專案）整理出來的做法。任何新的網頁專案，先照這份對齊顆粒度與習慣，再開始做。

## 1. 開工對齊

1. 先讀專案的交接記憶檔（若有），確認目前狀態與待辦，不要重問已經決定的事。
2. 用一兩句話確認要交付什麼（網站、單頁、儀表板、skill），以及給誰看。能從上下文判斷的就不要問。
3. 方向還不清楚、而且做錯會很貴時（例如一個全新的頁面概念），**先做一頁草圖**給他看，不要先寫長篇提案。
4. 需要大量蒐集公開資料時，寫一段 prompt 讓他交給 ChatGPT 蒐集，節省 Claude 的 token。

## 2. 他的工作方式

- **直接做出成品給他看**，不要先討論選項；他看成品比看討論容易判斷。
- 他常在一則訊息裡放好幾件事：自己拆成任務、自己判斷完成標準、哪些不要動、用多少力氣，不要請他拆。
- 他會說「顺手能修的就修，需要討論的就討論」：小問題直接改，牽涉方向、品牌、法律、金錢的才拿出來問，並在問題本身說清楚背景。
- **推送前先問**；他常說「之後一併推」，就先在本機 commit，最後一次推。
- **每一輪都記錄**：開發紀錄寫「我的要求、決定（含理由）、驗證」，同步更新變更紀錄與交接記憶檔。這些紀錄同時是作品集裡「一步一步討論出來」的證明。
- 回覆要短：做了什麼、要他做什麼、待決定的事。不重述每一步。
- 他不是該領域的專家（例如不是分析師）時，主動補上專業使用者的判斷。
- 在意成本：選方案時說明 token、時間與費用，估算要註明假設。

## 3. 品質標準

**文字**
- 介面上說明資料的文字：書面、正式、像論文；操作提示：白話。都要精簡。
- 台灣繁體中文用語。標題簡潔易懂。

**視覺與互動**
- 參考權威、成熟的網站（例如臺北市資料大平臺、GOV.UK、公開資訊觀測站），並實際讀它們的 CSS 數值，不憑印象。
- 不要「AI 感」：數字不要一直跳、不要為了花俏而花俏、介面不要像模板。
- 「沒什麼用但很帥」的小互動是加分：光影、3D、物理效果、捲動動畫。但要有退路（窄螢幕、不支援 WebGL、減少動態效果時改用簡單版本）。
- 絕對不能跑版：手機（390px）、平板（1024px）、桌機（1440px）、深色模式都要看。
- 動畫速度宜快，不要讓人等。
- logo 要去背，深色模式另備版本。

**專業感**
- 主要介面給專業使用者。新手教學、名詞解釋放在邊緣（例如頁尾），因為看不懂的人可以請 AI 解釋頁面。

**資料與誠信**
- 沒有資料就留位置（例如「待接 TEJ 共識資料」），**不猜數字**。
- 每個數字都要能回溯出處。
- 不捏造紀錄、支持者、評論或付款流程；展示用的功能（例如小額支持）按鈕維持「即將開放」。
- 財經相關：台股慣例紅漲綠跌；加上「不構成投資建議」。

## 4. 上線前的 UI／UX 審查

每個網頁專案在交付或上線前做一次，結果寫進開發紀錄。

1. **人物誌**：至少兩種使用者，例如「每天用、要快的老手」與「第一次來的新手」，寫出他們各自要完成的事。
2. **認知走查**：替每種人列出常做的任務，在瀏覽器裡一步一步實際操作，記下每一個「不知道下一步」「要繞路」「要回頭找」的地方。整理成表格：誰／任務／卡在哪／處理。
3. **可用性原則**（Nielsen 十大原則），特別檢查：
   - 用語是否對應使用者的語言
   - 老手是否有捷徑（鍵盤、上一筆／下一筆、直接跳轉）
   - 是否要靠記憶回頭找（同類項目之間能不能直接切換）
   - 空狀態、找不到頁面、錯誤時有沒有清楚的下一步
4. **設計品質檢查**：用程式量測每一頁
   - 字級小於 12.5px 的文字
   - 文字對比小於 4.5:1
   - 手機觸控範圍小於 40px
   - 橫向捲動（文件與主要容器）
   - 主控台錯誤
5. **連續操作**：從一個項目跳到同類的下一個、搜尋結果直達內容所在位置、返回時保留捲動位置、分享連結有預覽。
6. **入口與導覽**：第一次進來的人從首頁能不能找到所有主要功能；導覽列是否涵蓋主要入口（列表、目錄、行事曆、我的清單、搜尋、關於）。
7. **上線後**：開流量統計（不用 cookie 的服務），並找 5 位真實使用者照任務操作、觀察。

## 5. 靜態網站的技術預設

- 純靜態（GitHub Pages），沒有後端；資料內嵌或用 JS 索引檔，雙擊 HTML 也能看。
- 版面改「模板」再複製成輸出檔，兩者保持一致。
- GitHub Actions：推送後先跑檢查程式（例如擋下不該公開的資料），通過才發布；actions 固定到 commit SHA，並開 Dependabot。
- 安全：Content-Security-Policy、Referrer-Policy、不載入外部程式、外部連結 `rel="noopener"`、跨頁訊息檢查來源、使用者輸入不經 innerHTML。
- 搜尋引擎與分享：每個主要項目產生靜態頁（獨立標題、描述、分享圖、結構化資料）＋ `sitemap.xml`；首頁 og 圖 1200×630。
- 必備頁面：找不到頁面、關於本站（含更新方式）、意見回饋（GitHub Issue 預填、Email 或表單）、使用條款與隱私權（草擬後請法務審閱）。
- 自動化測試：Playwright 腳本收進儲存庫（例如 `tools/site_test.js`），每次改完都跑。

## 7. 在 Cowork 環境的眉角

- Cowork 不能 `git push`：在本機 commit，請他在自己的終端機推送。
- Cowork 預設不能刪檔：git 會留下 `.lock`，改名到 `.git/stale-*` 即可；需要刪除時先請他授權。
- 雲端做、打包傳到他的電腦再解開；解開時用複製覆蓋（不能刪檔）。
- 他電腦上的 Python 是 3.10：f-string 的運算式裡不能有反斜線。
- 本機預覽用 `python -m http.server`，伺服器在對話之間會停，要重開。
