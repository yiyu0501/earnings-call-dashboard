# 案例集

16 場法說會、16 種情境，用來確認 skill 在各種狀況下都能產出合格的儀表板。另外有一層全庫掃描，把 TEJ 逐字稿資料庫的 484 場全部跑過程式。每次修改 skill 後，這些都要重跑一次。

## 四層測試

| 層 | 做什麼 | 工具 | 最近一次結果 |
|---|---|---|---|
| 全庫掃描 | 484 場全部跑過讀檔切段與語調計分，抓程式當掉與資料異常 | `tools/smoke_all.py` | 0 場當掉 |
| 回歸測試 | 16 個案例從頭跑完整流程，互動版與表格版都要通過檢查 | `tools/run_cases.py` | 16／16 通過 |
| 反向測試 | 故意埋 11 種錯誤，確認檢查程式都擋得下來 | `tools/negative_tests.py` | 11／11 擋下 |
| 瀏覽器實測 | 每個案例在桌面與手機寬度實際打開、操作報告稿與方法說明 | 內含於回歸測試 | 無錯誤、無橫向捲軸 |

## 案例一覽

### 第一批（一般情境）

| 案例 | 測什麼 | 抓到的問題 |
|---|---|---|
| 01 台積電 2026Q2 | 英文、有上一場、22 題 Q&A、4 項上修 | 前次數值照抄「mid-to-high 50s」（使用者發現）→ 規則要求寫出中文意思 |

| 03 群創 2026Q2 | 只收錄 1,474 字、沒有財務數字 | 1 個語調詞就得 +1.00 → 少於 10 個詞標「詞數太少」 |
| 04 佳世達 2026Q2 | 資料庫沒有 Q&A 段、自訂表格模組 | 公司名稱的「佳」被算成正向詞 42 次；書面問答被標成「報告」 |
| 05 台積電（無上一場） | 沒有上一場、沒有報告稿 | 比較欄位要自動隱藏、報告稿改自動組稿 |

## 全庫掃描發現的 TEJ 資料問題

| 問題 | 影響場次 | skill 怎麼處理 |
|---|---|---|
| 同一段內容重複收錄上百次 | 南亞科 1/19（93%）、台積電 1/15（67%）、樺漢 7/14（32%，轉寫迴圈） | 刪除重複長句與連續迴圈，第一次出現的保留，並發出警告 |
| 整場標成同一人，提問混在裡面 | 台積電 1/15、南亞科 1/19、定穎投控 5/7 | 偵測後改用全文計分，提醒 AI 自己判斷誰在說話 |
| 沒有管理層，只有法人關係人員 | 廣達 8/13、強茂 5/15 等 | 改用法人關係人員的發言計分，頁面標明計分範圍 |
| 和上一場幾乎相同 | 順達、台灣大、遠傳、環球晶、瑞昱、欣興各一組 | 提醒 AI 比對期間，相同就不做前後比較 |
| 內容過短 | 致伸 2/26（153 字） | 警告內容不足，詢問使用者是否繼續 |

## 資料夾內容

```
01_台積電_2330_2026Q2/
├── case.json         這個案例測什麼、怎麼取出逐字稿
├── dashboard.json    AI 依 skill 規則寫的內容
├── tone.json         語調分數（程式算）
├── keywords.json     關鍵字次數（程式算）
├── check.json        最近一次的檢查結果
├── transcript/       逐字稿（TEJ 資料，公開版本不附，需自行取出）
└── out/              互動版、表格版、桌面與手機截圖
```

## 怎麼重跑

1. 依每個案例 `case.json` 的 `extract` 指令取出逐字稿到 `transcript/`
2. `python tools/run_cases.py <skill 資料夾> cases`
3. `python tools/negative_tests.py <skill 資料夾> cases/01_台積電_2330_2026Q2`
4. `python tools/smoke_all.py <skill 資料夾> TEJ逐字稿資料庫_2026.xlsx smoke.json`
